# 🤖 AI 에이전트와 함께 설치·운영하기

> 관리자가 **Claude Code · Codex** 같은 AI 에이전트에게 서버 SSH 접속을 열어 주고, 설치와 점검, 일상 운영을 함께 하는 방법입니다.
>
> 에이전트가 읽고 따르는 규칙은 저장소 루트의 [`AGENTS.md`](../AGENTS.md)에 있습니다.
>
> 이 방식은 **편의 기능**입니다. 서버를 바꾸는 책임과 승인은 여전히 관리자에게 있습니다.

---

## 🧭 어떤 방식인가요

| | 방식 | 설명 |
|---|---|---|
| 💻 | **A. 내 PC 에서 에이전트 실행** | 내 PC 의 Claude Code · Codex 가 `ssh` 로 서버에 접속해 명령을 실행합니다 |
| 🖥 | **B. 서버 안에서 에이전트 실행** | 서버에 접속해 그 안에서 에이전트를 실행합니다(서버에 에이전트 CLI 가 있어야 합니다) |

두 방식 모두 에이전트는 서버에서 **관리자 계정이 가진 권한**으로 일합니다. 그래서 아래 «안전 규칙»이 중요합니다.

---

## 🔐 준비

1. **SSH 키 인증**을 쓰세요. 비밀번호를 에이전트 대화에 입력하지 마세요.
2. 에이전트가 쓰는 계정은 지금은 **관리자 계정**입니다. (전용 계정·제한된 sudo 는 다음 버전 `agent` 모듈로 계획되어 있습니다.)
3. `sudo` 는 비밀번호가 필요합니다. root 권한이 필요한 명령은 에이전트가 «`! sudo …` 를 실행해 주세요»라고 안내하면 **관리자가 직접 실행**합니다.
4. 서버에서 에이전트에게 규칙을 읽히려면: 설치된 `/opt/<접두어>/AGENTS.md`(또는 저장소의 `AGENTS.md`)를 먼저 읽으라고 지시합니다. Claude Code 는 프로젝트의 `CLAUDE.md`, Codex 는 `AGENTS.md` 를 자동으로 읽습니다.

---

## 🚀 설치를 맡길 때 (프롬프트 예시)

> 이 서버에 devmaru 를 설치해 줘.
>
> - 먼저 `/opt/devmaru-kit/AGENTS.md` 를 읽고 규칙을 따라.
> - 설정: 접두어 `myorg`, 서비스 이름 `우리 실험실`, 도메인 `example.org`, 관리자 계정 `ubuntu`, 모듈은 기본값 + backup.
> - 설정 파일을 만든 뒤 `--plan` 으로 계획을 먼저 보여 주고, 내가 승인하면 설치해.
> - root 권한이 필요한 명령은 `! sudo …` 형태로 알려 주면 내가 실행할게.
> - 끝나면 `doctor --json` 결과를 요약하고, 설치 화면의 «첫 설정 체크리스트»를 정리해 줘.

---

## 🩺 점검·운영을 맡길 때 (프롬프트 예시)

> 서버 상태를 점검해 줘. `sudo devmaru-doctor --json` 으로 확인하고, 경고나 실패가 있으면 원인을 로그에서 찾아 요약해 줘. 고치기 전에 계획을 먼저 보여 줘.

> 새 회원 alice(alice@example.org)를 등록해 줘. 초기 비밀번호는 대화에 옮기지 말고, 어디에 표시되는지만 알려 줘.

> 새 릴리스가 나왔는지 확인하고, 업데이트 전에 필요한 사전 점검(`member-update-all --check`, tmux 사용 중인 회원 수)을 정리해 줘. 실행은 내 승인 뒤에.

## 🚦 안전 규칙 요약

| 구분 | 에이전트가 하는 일 |
|---|---|
| 🔎 읽기 전용 | `doctor`, `--plan`, `--check`, `status`, 로그 조회 — **바로 실행** |
| ✋ 승인 필요 | 회원 삭제 · 업데이트 · 강제 종료 · 암호 교체 · 설정 변경 — **명령을 준비해 보여 주고 승인 후 실행** |
| ⛔ 하지 않음 | 비밀(`*.env`, `secrets/`, 토큰, 페어링 링크) 열람·출력 · 회원 대화·작업물 열람 · sudo 비밀번호 우회 |

> ⚠️ **에이전트도 실수합니다.** 파괴적인 명령은 반드시 직접 확인하고 승인하세요.
>
> 회원 삭제와 같이 되돌릴 수 없는 작업은 특히 그렇습니다.

## 📋 기계가 읽기 쉬운 점검: `doctor --json`

```bash
sudo <접두어>-doctor --json
```

```json
{"status": "pass", "warnings": 0, "brand": "우리 실험실", "domain": "example.org",
 "checks": [{"status": "ok", "message": "컨테이너 postgres (healthy)"}, …]}
```

- `status` — 전체 결과(`pass` / `fail`), 종료 코드도 같습니다(통과 0 · 실패 1).
- `checks[].status` — `ok` · `warn` · `fail`.

## 🤖 전용 에이전트 계정 (선택 모듈 `agent`, 1.2.0 초안)

- 🔑 **전용 계정** — SSH 키 전용, 비밀번호 잠금, 만료일 설정, 키는 관리자가 `<접두어>-agent-key` 로 등록
- 🛡 **제한된 sudo** — 허용한 읽기성 명령(점검·계획·백업)만 비밀번호 없이, 파괴적 명령은 사람 승인
- 📜 **감사 로그** — `sudo <접두어>-agent-audit` · 자세히는 [에이전트 계정](AGENT.md)

> 📖 명령 전체는 [운영 가이드](OPERATIONS.md), 설치는 [설치 가이드](INSTALL.md)를 보세요.
