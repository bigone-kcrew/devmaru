> 명령은 서버에 SSH 로 접속해 `sudo` 권한으로 실행합니다.

## 0. 설치 전에 준비할 것

| 준비물 | 설명 |
|---|---|
| **서버** | Ubuntu **26.04 LTS** (x86_64) · 메모리 8GB 이상(회원이 많으면 16GB 이상) ·<br>디스크 여유 60GB 이상 · 인터넷 연결 |
| **도메인** | 예: `example.org`. 도메인 관리 화면에서 **A 레코드**를 만들어 서버의 공인 IP 를 가리키게 합니다 |
| **DNS 레코드** | `example.org` 와 `portal.example.org` 는 필수입니다.<br>나머지(`n8n.`, `files.` 등)와 회원 사이트(`<ID>.example.org`)는<br>**와일드카드 `*.example.org`** 한 줄로 해결하는 것을 권장합니다 |
| **포트** | 80 · 443 이 외부에서 서버로 들어올 수 있어야 합니다(인증서 자동 발급).<br>SFTP 를 쓰면 2022 도 필요합니다 |
| **관리자 계정** | 서버에 이미 있는 리눅스 계정(보통 처음 만든 계정). `sudo` 가능해야 합니다 |

> **공인 도메인이 없는 내부망·시험 환경이라면**
>
> 설정 파일에 `TLS_MODE=internal` 을 넣고 설치하세요.
>
> 내부 인증서를 쓰므로 브라우저가 경고를 띄웁니다. 자세한 내용은 아래 «DNS·포트 준비» 를 보세요.

### 준비물·하드웨어 기준

사전 점검(`00-preflight`)이 실제로 **막는 것(실패)** 과 **알려만 주는 것(경고)** 입니다. «실측» 칸이 «없음» 인 값은 시험해 보지 못한 것이니 참고만 하세요.

| 항목 | 막는 기준(실패) | 권장(경고) | 실측 |
|---|---|---|---|
| **OS** | x86_64 가 아니면 실패 | Ubuntu 26.04 가 아니면 경고만 | Ubuntu 26.04.1 x86_64 **에서만** 시험했습니다.<br>다른 배포판·버전·ARM<br>은 시험하지 않았습니다 |
| **메모리** | 7GB 미만 | 16GB 미만이면 경고(회원이 여러 명일 때) | 8GB(4코어)에서 설치가 끝까지<br>통과했습니다(리허설 VM).<br>회원 수별 한계는 **실측 없음** |
| **CPU** | (막지 않음) | 4코어 미만이면 경고 | 4코어에서 통과 |
| **디스크** `/srv` | 여유 30GB 미만 | 60GB 미만이면 경고 | Golden 이미지는 약 8GB(사무 문서 도구 포함 시 약 +0.6GB).<br>80GB 디스크 VM 에서 통과.<br>회원 1명당 사용량·회원 수별 권장 용량은 **실측 없음** |
| **디스크** `/var/lib` (도커) | (막지 않음) | 여유 40GB 미만이면 경고 | — |
| **관리자 계정** | 지정한 리눅스 계정이 없으면 실패 | — | — |
| **실행 권한** | root(`sudo`) 가 아니면 실패 | — | — |
| **포트 80 · 443** | 이미 **다른 프로그램**(caddy 제외)이 쓰면 실패 | — | — |
| **소요 시간** | — | — | 처음부터 끝까지 약<br>15~20분(리허설 VM,<br>네트워크에 따라 다름) |

**인터넷이 필요한 곳**

- 사전 점검: `github.com` · `registry-1.docker.io` · `deb.nodesource.com` · `dl.cloudsmith.io` — **하나라도 응답이 없으면 설치가 중단**됩니다(사내 프록시·방화벽이면 먼저 열어야 합니다).
- DNS 점검: 서버의 공인 IP 를 알아내려고 `api.ipify.org` 를 부릅니다(`--skip-dns` 로 건너뛸 수 있음).
- 설치 한 줄 명령: 킷을 받는 GitLab 주소.
- 설치 중: 패키지(apt) 저장소, Docker 이미지, Golden 이미지 빌드에 쓰는 외부 저장소.
- 설치 뒤: Paseo 앱 연결은 릴레이를 거치므로 서버가 인터넷으로 나갈 수 있어야 합니다. 인증서 자동 발급(Let's Encrypt)도 인터넷이 필요합니다.

### DNS·포트 준비

| 항목 | 해야 할 일 |
|---|---|
| **DNS 레코드** | 도메인 관리 화면에서 **와일드카드 `*.example.org`** A 레코드 한 줄(+ `example.org` 자체)<br>또는 **호스트별 A 레코드**를 서버의 공인 IP 로 만듭니다.<br>호스트별이라면 최소 `example.org` · `portal.example.org` 가 필요하고,<br>선택 서비스를 켜면 해당 호스트(`n8n.` `files.` `smb.` 등)도 필요합니다.<br>회원 사이트는 `<ID>.example.org` 라 회원이 늘 때마다<br>레코드를 만들지 않으려면 와일드카드가 편합니다 |
| **확인** | `dig +short portal.example.org` 가 서버 공인 IP 와 같아야 합니다.<br>사전 점검도 같은 비교를 해서 다르면<br>**경고**를 냅니다(막지는 않습니다) |
| **80 · 443** | 인터넷에서 서버로 들어올 수 있어야 합니다.<br>인증서 발급(ACME HTTP-01)은 **80 포트**로<br>확인하므로 443 만 열면 발급되지 않습니다 |
| **집·사무실 서버** | 공유기에서 80 · 443(SFTP 를 쓰면 2022)을 서버로 **포트 포워딩**하고,<br>서버의 사설 IP 를 고정(DHCP 예약)하세요.<br>공인 IP 가 바뀌는 회선이면 DNS 도<br>따라 바뀌어야 합니다(고정 IP 권장) |
| **CGNAT 주의** | 통신사가 공인 IP 를 여러 가정에 나눠 쓰게 하면(CGNAT)<br>포트 포워딩이 되지 않습니다.<br>공유기 화면의 WAN IP 와 `curl https://api.ipify.org`<br>결과가 **다르면** 의심하세요.<br>이 경우 고정 공인 IP 를 신청하거나 클라우드 서버를 쓰세요 |
| **방화벽** | 서버 방화벽이 80 · 443 · SSH 를 막지 않는지 확인합니다.<br>킷의 `<접두어>-firewall` 은 설치기가 적용하지<br>않으며 직접 `plan` 으로 확인 후 적용합니다([FIREWALL](FIREWALL.md)) |

> **도메인 없이 시험하기**
>
> 설정 파일에 `TLS_MODE=internal` 을 넣고, 설치할 때 `--skip-dns` 를 붙입니다. Caddy 가 자체(내부) 인증서를 쓰므로 인터넷에서 80 포트로 확인받는 과정이 필요 없습니다. 이 방식으로 **리허설 VM 설치가 끝까지 통과**했습니다.
>
> **한계:** 브라우저가 «안전하지 않음» 경고를 띄웁니다. 모바일 앱·외부 도구가 인증서를 거부할 수 있고, 회원 사이트를 다른 사람에게 보여 줄 수 없습니다. 이름은 내 PC 의 `hosts` 파일에 직접 적어 줘야 풀립니다.
>
> **공인 인증서(Let's Encrypt) 발급은 아직 시험하지 못했습니다.** 리허설 VM 은 80/443 이 인터넷에 열려 있지 않았기 때문에 `TLS_MODE=acme`(기본)의 실제 발급은 확인하지 못했습니다. 첫 설치에서 인증서가 안 받아지면 아래 «문제 해결» 과 `journalctl -u caddy -n 50` 을 확인하고, 막히면 [SUPPORT](SUPPORT.md) 의 진단 묶음을 첨부해 알려 주세요.

### Windows PC 에 설치하려면

데브마루는 **Ubuntu 26.04 서버**를 기준으로 만들었습니다. Windows 11 PC 를 서버로 쓴다면 방법이 둘입니다.

- **권장 — VM**: Hyper-V(Windows Pro·Enterprise) 또는 VirtualBox 의 **Ubuntu Server 26.04 LTS VM** 안에서 이 문서의 순서를 그대로 따릅니다. Windows 위에서 직접 시험하지는 않았습니다(Ubuntu 26.04 VM 에서는 시험했습니다).
- **실험적 — WSL2**(Windows 11): 준비 스크립트 `windows/install-windows.ps1` 을 씁니다. 아래 «WSL2 (실험적)» 을 참고하세요.

**VM 으로 설치할 때**: 메모리 8GB 이상(16GB 권장) · CPU 4코어 · 디스크 60GB 이상을 VM 에 할당하고, 다른 PC 나 외부에서 접속하려면 NAT 가 아닌 **브리지 네트워크**(Hyper-V «외부» 스위치 · VirtualBox «어댑터에 브리지»)로 연결합니다. Windows 가 켜질 때 VM 도 자동으로 시작되게 설정하세요.

**VM 만드는 순서** (일반적인 방법입니다. 데브마루를 Windows 위의 VM 에서 직접 시험한 것은 아니므로, 화면 이름이 Windows·VirtualBox 버전에 따라 다를 수 있습니다.)

1. **Ubuntu Server 26.04 LTS ISO** 를 Ubuntu 공식 사이트에서 받습니다(데스크톱판이 아니라 *Server*).
2. VM 을 만듭니다.
   - **Hyper-V**: «2세대» · 메모리 16GB(고정 권장) · 가상 CPU 4개 · 디스크 60GB 이상 · 네트워크는 «외부» 가상 스위치. 보안 부팅 때문에 ISO 가 부팅되지 않으면 VM 설정의 보안에서 템플릿을 «Microsoft UEFI 인증 기관» 으로 바꾸거나 보안 부팅을 끕니다.
   - **VirtualBox**: 유형 Linux · Ubuntu(64-bit) · 메모리 16GB · CPU 4개 · 디스크 60GB 이상 · 네트워크 어댑터를 «어댑터에 브리지».
3. Ubuntu Server 를 설치합니다. 설치 중 **OpenSSH server** 를 선택하고, `sudo` 가 되는 관리자 계정을 만듭니다.
4. 공유기에서 VM 의 IP 를 **고정**(DHCP 예약)하고, 외부에서 쓰려면 80·443(필요하면 SSH)을 그 IP 로 포워딩합니다.
5. **VM 안에서** 이 문서의 «설치 명령»(`curl … | sudo bash`)을 그대로 실행합니다. 이후 순서는 일반 Ubuntu 서버와 같습니다.
6. 서버로 계속 쓰려면 Windows 쪽도 챙깁니다.
   - Windows 가 켜질 때 VM 자동 시작: Hyper-V 는 VM 설정의 «자동 시작 동작» 을 «항상 자동으로 시작» 으로, VirtualBox 는 작업 스케줄러에서 `VBoxManage startvm "<VM 이름>" --type headless` 를 로그온 때 실행하게 합니다.
   - 절전·최대 절전을 끄고, Windows 업데이트의 자동 재부팅 시간을 사용 시간 밖으로 잡습니다(재부팅되면 VM 도 잠시 내려갑니다).


#### WSL2 (실험적)

관리자 PowerShell 에서 `windows\install-windows.ps1` 을 실행합니다(`-Apply` 없이 실행하면 **계획만** 보여 줍니다). 이 스크립트는 Windows 쪽 준비만 합니다.

- WSL distro `Ubuntu-26.04` 설치(systemd 켜기)
- 부팅 때 distro 를 켜 두는 **작업 스케줄러 작업**(WSL 은 세션이 없으면 곧 내려가므로 필요합니다)
- LAN 접속: 기본 **mirrored 네트워킹**(`.wslconfig`, 포트 전달 불필요). `-Network portproxy` 를 주면 포트 전달 + IP 갱신 작업 방식
- **같은 LAN 에서만** 열리는 방화벽 규칙(웹 80·443, 회원 SSH `-SshPort` 기본 2222)
- 되돌리기: `.\install-windows.ps1 -Uninstall -Apply` (distro 까지 지우려면 `-RemoveDistro`)

끝나면 `wsl -d Ubuntu-26.04 -u root` 로 distro 안에 들어가 이 문서의 설치 순서를 그대로 따릅니다(설정 파일에 `SSH_PORT=2222`, 공인 도메인이 없으면 `TLS_MODE=internal`).

> **실험적 지원입니다.** 시험한 범위: Windows 11 Pro 10.0.26300 · WSL 2.7.3 **한 대**(Intel N100, 메모리 16GB, PC 는 자동 로그인 상태), Windows PowerShell 5.1 과 PowerShell 7 모두.
>
> 확인한 것 — 이 스크립트로 distro 를 만든 뒤 **처음부터 설치**(모듈 postgres·caddy·golden·portal·files·n8n)·회원 등록·회원 SSH 경계(컨테이너 안에서만 실행, 호스트 경로 숨김, 포트 전달 거부)·한글 pptx→pdf 변환, 같은 LAN 의 다른 기기에서 포털·files·n8n·SSH 접속, 불필요한 내부 포트(5432·8080·5678 등)는 LAN 에서 닫힘, **재부팅 뒤 자동 복구**(mirrored·portproxy 두 방식 모두 약 2분 안에 포털 응답 — n8n 은 그보다 1분쯤 더 걸림), 두 방식을 오가는 전환과 `-Uninstall`.
>
> 확인하지 못한 것 — 자동 로그인이 꺼진 PC, 다른 Windows 빌드, 회원이 많을 때의 부하, 방화벽·Samba·Cockpit 모듈, WSL IP 가 실제로 바뀌는 경우(갱신 작업은 일부러 IP 를 틀리게 만들어 시험했습니다). WSL2 는 **Windows 와 포트를 공유**하므로 Windows 쪽 OpenSSH 는 22번, WSL 안 회원 SSH 는 2222번으로 나눕니다.
>
> 운영 서버로는 Ubuntu 서버나 VM 을 권장합니다. WSL2 는 개인 PC 에서 시험·소규모로 쓸 때 고려하세요.

## 1. 설치 시작

### 1. 터미널로 설치

```bash
curl -fsSL https://raw.githubusercontent.com/bigone-kcrew/devmaru/main/install.sh | sudo bash
```

GitHub 에서 받습니다. GitLab 에서 받으려면 `sudo DEVMARU_SOURCE=gitlab bash` 로 바꿉니다.

스크립트는 다음 순서로 일합니다.

1. OS 와 CPU 를 확인합니다.
2. 릴리스 파일을 받아 **sha256 을 검증**합니다.
3. `/opt/devmaru-kit` 에 풀고 설치기(`devmaru-install`)를 실행합니다.

특정 버전을 받으려면 `DEVMARU_REF=<버전>`, 다른 주소에서 받으려면 `DEVMARU_URL=<tarball 주소>` 를 앞에 붙입니다.

### 2. 웹 화면으로 설치 (선택)

터미널 질문 대신 브라우저 화면으로 설치할 수 있습니다.

```bash
sudo python3 /opt/devmaru-kit/bin/devmaru-install --web
```

보안을 위해 기본은 **서버 안(127.0.0.1)에서만** 열립니다.
내 PC 에서는 SSH 터널을 먼저 엽니다.

```bash
ssh -L 8765:127.0.0.1:8765 <사용자>@<서버 주소>
```

그다음 내 PC 브라우저에서 터미널에 표시된 주소(`http://127.0.0.1:8765/?t=…`)를 엽니다.

- 질문 입력 → «설치 계획 확인» → «설치 시작» 순서입니다.
- 진행 단계와 로그가 실시간으로 표시됩니다.
- 실패하면 «이어서 다시 시도» 버튼이 나옵니다.
- 설치가 끝나면 터미널에서 `Ctrl+C` 로 닫으세요.

| **접두어** | 명령·폴더·이미지 이름에 붙는 짧은 이름.<br>**처음에 한 번 정하고 바꾸지 않습니다.** 소문자로 시작,<br>소문자·숫자 2~12자 | `devmaru`(기본), `myorg` |
| **서비스 표시 이름** | 포털 등 화면에 보이는 이름(한글 가능) | `My Lab`, `우리 실험실` |
| **기본 도메인** | 위에서 준비한 도메인 | `example.org` |
| **포털 호스트 라벨** | 포털 주소의 앞부분 → `portal.example.org` | `portal` |
| **관리자 계정** | 이미 있는 리눅스 계정 | `ubuntu` |
| **관리자 이메일** | 인증서 만료 알림 등을 받을 주소 | `admin@example.org` |

| **시간대** | 컨테이너 시간대 | `Asia/Seoul` |

필수 구성요소(**postgres · caddy · golden · 포털**)는 항상 설치됩니다.

## 4. 설치가 끝나면

```bash
sudo <접두어>-doctor                                         # 상태 점검 (전부 «성공» 이어야 합니다)
sudo <접두어>-member-add alice --email alice@example.org     # 첫 회원 등록
```

회원 등록이 끝나면 **초기 비밀번호**와 온보딩 파일 위치가 화면에 표시됩니다(메일 자동 발송을 설정하지 않은 경우).
회원에게 전달한 뒤 `<접두어>-onboarding-seal <ID>` 로 임시 파일을 정리하세요.

| | 주소 |
|---|---|
| **포털** | `https://portal.<도메인>/` — Guide 에 회원용 시작 안내가 있습니다 |
| **회원 사이트** | `https://<ID>.<도메인>/…` |
| **파일 서비스** | `https://files.<도메인>/` |

### 설치 후 첫 설정 체크리스트 (서비스별)

설치가 끝나면 설치기도 같은 내용을 화면에 출력합니다. 비밀 값은 출력하지 않고 **위치만** 알려 줍니다.

| 서비스 | 설치기가 해 주는 것 | 관리자가 할 것 |
|---|---|---|
| **PostgreSQL** | 컨테이너 · 확장(pgvector · pg_bigm) · 관리자 비밀번호 생성(`/opt/<접두어>/config/env/postgres.env`) · 회원 DB 자동 | 없음 (직접 접속: `sudo docker exec -it postgres psql -U postgres`) |
| **n8n** | 컨테이너 · DB 연결 · 암호화 키 생성 | **처음 여는 사람이 소유자 계정을 만듭니다** — 관리자가 먼저 열어 만드세요. 암호화 키(`config/env/n8n.env`)는 백업. 회원은 소유자가 초대 |
| **Files(SFTPGo)** | 컨테이너 · API 키 · 공용 폴더 · 회원 계정 자동 생성 · SSH 비밀번호 동기화 | 관리자 화면 `/web/admin` 이 필요하면 `admin` / 비밀번호는 `/opt/<접두어>/compose/sftpgo/.env` |
| **Kordoc · MarkItDown · Crawl4AI** | 키 생성 · 회원 컨테이너에 MCP 자동 연결 | 없음 |
| **Uptime Kuma** | 컨테이너 · 관리자 대역 전용 Caddy 주소(`uptime.<도메인>`) | 처음 열면 데이터베이스 종류(SQLite 권장)를 고르고 관리자 계정 생성 |
| **Cockpit** | 설치 · `127.0.0.1` 바인딩 · 관리자 대역 전용 Caddy 주소 | 리눅스 관리자 계정으로 로그인 |
| **Ollama** | 컨테이너(`127.0.0.1:11435`) | **모델이 비어 있습니다** — `sudo docker exec <접두어>-ollama ollama pull <모델>`. 현재 이 킷의 다른 구성요소는 Ollama 를 쓰지 않습니다 |
| **백업(restic)** | 저장소 · 암호 생성 | 암호(`/etc/<접두어>/secrets/restic-repository-password`)를 **서버 밖에도 보관**, `<접두어>-backup-run` 실행 |
| **회원 SSH 접속** | 로그인 시 개발환경 자동 입장 · 회원 그룹만 비밀번호 로그인 · 비밀번호 변경 동기화 | 서버 sshd 포트·방화벽 확인. 포트가 22 가 아니면 설정 파일에 `SSH_PORT` 를 넣어 안내 문구를 맞춤 |

> **회원 접속 규칙**
>
> 회원은 처음 SSH 로그인에서 **비밀번호를 바꿔야** 합니다(강제).
>
> 바꾼 비밀번호는 Files(SFTPGo) 와 Samba(설치한 경우)에도 자동으로 적용됩니다.
>
> 관리자 계정은 호스트에 그대로 남고, 회원 그룹 계정만 개발환경으로 들어갑니다.
>
> `ssh 회원@서버 '명령'` 도 호스트가 아니라 개발환경 안에서 실행됩니다(sshd ForceCommand). 포트 전달(-L)은 기본으로 막혀 있습니다.

### Paseo 로 접속하기 (터미널 없이)

회원을 등록하면 온보딩 폴더(`/srv/<접두어>/onboarding/<ID>`)에 다음 파일이 만들어집니다.

- `pairing.png` — QR
- `pairing-url.txt` — 링크

회원이 **Paseo 앱**에서 QR 을 스캔하거나 링크를 열면 자기 컨테이너의 Paseo 데몬에 연결됩니다.

> **페어링 링크는 영구 자격증명처럼 다루세요**
>
> 재발급해도 같은 값입니다.
>
> 회원에게만 전달하고, 전달이 끝나면 `<접두어>-onboarding-seal <ID>` 로 폴더의 임시 파일을 지우세요.

- 서버가 인터넷으로 나갈 수 있어야 합니다(릴레이를 통해 연결합니다). 64MB 이하 파일 내려받기도 릴레이로 됩니다.
- 음성 입력·낭독 모델(영어 전용, 용량 큼)은 기본 제외입니다. 필요하면 설정 파일에 `GOLDEN_VOICE=1`.
- 사무 문서 도구(LibreOffice Impress·Writer·Calc, 한글 글꼴 Noto CJK·Nanum — pptx·docx·xlsx 변환과 확인)는 **기본 포함**입니다(이미지 약 +570MB, 빌드 때 Ubuntu 저장소 `archive.ubuntu.com` 에서 받습니다). 용량이 부담이거나 저장소에 접근할 수 없으면 설정 파일에 `GOLDEN_OFFICE=0` 으로 제외하세요.

## 6. 문제 해결

| 증상 | 확인 |
|---|---|
| 사전 점검에서 DNS 경고 | A 레코드가 서버 공인 IP 를 가리키는지 확인합니다(`dig +short portal.<도메인>`).<br>아직 전파 전이면 몇 분 뒤 `--resume` |
| 인증서가 안 받아짐 (포털 HTTPS 응답 없음) | 80/443 포트 개방, DNS, `journalctl -u caddy -n 50` |
| Golden 빌드 실패 | `/var/log/<접두어>-golden-build.log` 의 끝부분.<br>대개 일시적 네트워크 오류이니 `--resume` 으로 재시도합니다 |
| 서비스가 안 올라옴 | `docker ps -a`, `docker logs <컨테이너>` |
| 메모리 부족 | 선택 서비스를 줄이거나(`--skip`), 서버 메모리를 늘리세요 |

### 자주 나는 실패와 대처

리허설과 소스에서 **원인을 확인한 것만** 적었습니다. 여기에 없는 증상은 원인을 모르는 것이니 추측으로 고치지 말고 아래 «도움 요청» 을 따르세요.

| 증상 | 원인(확인된 범위) | 대처 | 근거 |
|---|---|---|---|
| 패키지 설치 단계에서 apt 가 멈추거나 «잠금» 오류 | 서버의 자동 업데이트(`apt-daily`)가 apt 잠금을 잡고 있음 | 설치기는 잠금을 최대 300초 기다립니다. 그래도 실패하면 자동 업데이트가 끝난 뒤 `--resume` | 리허설 VM 에서는 이 타이머를 꺼서 피했고, Cockpit 설치가 이 충돌로 실패하던 것을 1.1.0 에서 고쳤습니다 |
| 사전 점검 «포트 80 를 다른 프로그램이 쓰고 있습니다» (443 도 같은 문구) | 이미 웹 서버(caddy 가 아닌 것)가 포트를 점유 | 해당 프로그램을 멈추거나 포트를 비운 뒤 다시 실행(`ss -ltnp 'sport = :80'` 으로 확인). caddy 가 쓰는 경우는 재설치로 보고 통과합니다 | 사전 점검 동작. 리허설 호스트에서도 기존 Caddy 가 80/443 을 써서 별도 VM 을 썼습니다 |
| 사전 점검 «인터넷 연결 실패: …» | 해당 주소로 나가는 연결이 막힘(방화벽·프록시·DNS) | 위 «인터넷이 필요한 곳» 을 열고 다시 실행 | 사전 점검 동작 |
| 사전 점검 DNS 경고 | A 레코드가 없거나 서버 공인 IP 와 다름(전파 전일 수도 있음) | `dig +short portal.<도메인>` 확인. 설치는 막지 않지만 공인 인증서는 DNS 가 맞아야 받아집니다. 내부망 시험이면 `--skip-dns` | 사전 점검 동작 |
| 사전 점검 «여유 NGB — 최소 30GB 필요» | `/srv` 여유 부족 | 디스크를 늘리거나 `/srv` 를 큰 디스크로 옮긴 뒤 다시 실행. 설치 뒤에는 `docker system df` 로 이미지·캐시 확인 | 사전 점검 기준·운영 가이드 |
| Golden 이미지 빌드 중 실패 | 대개 일시적 네트워크 오류(문서 기준) | `/var/log/<접두어>-golden-build.log` 끝부분 확인 후 `--resume` | 로그 위치·재개 절차는 확인됨. «대개 네트워크» 는 개별 사례로 검증하지 못했습니다 |

> GID 충돌(`groupadd: GID already exists`) 은 **재현·원인 확인을 하지 못해 표에 넣지 않았습니다.** 설치기는 접두어 그룹이 있으면 그 GID 를, 없으면 비어 있는 번호(1001부터)를 고릅니다.
