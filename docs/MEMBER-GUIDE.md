## 1. Paseo 앱으로 접속(터미널 없이)

관리자가 준 **QR 또는 링크**를 Paseo 앱에서 스캔하거나 열면 내 개발환경에 연결됩니다. 링크는 **영구 자격증명처럼** 다루세요. 남에게 주지 말고, 유출되면 관리자에게 알리세요.

## 2. SSH 로 접속

```bash
ssh <ID>@<서버 주소> [-p <포트>]
```

- **처음 로그인에서 초기 비밀번호를 새 비밀번호로 바꿔야 합니다**(강제). 바꾼 비밀번호는 파일 서비스(SFTPGo)에도 같이 적용됩니다.
- 로그인하면 호스트가 아니라 **내 개발환경(컨테이너)** 으로 들어갑니다. `ssh <ID>@서버 '명령'` 도 개발환경 안에서 실행됩니다.
- 포트 전달(`-L`)은 기본으로 막혀 있습니다.
- **SSH 키 등록:** 내 컴퓨터에서 키를 만들고(`ssh-keygen -t ed25519`), 공개키(`.pub` 한 줄)를 **개발환경 안에서** 등록합니다. 처음에는 비밀번호로 접속하거나 Paseo 앱 터미널을 쓰세요.
  - `<접두어>-ssh-key-add <공개키 파일>` (파일 없이 실행하면 한 줄을 붙여넣게 합니다) → 확인: `<접두어>-ssh-key-list` · 삭제: `<접두어>-ssh-key-remove SHA256:<지문>`
  - 개발환경의 홈(`/home/<ID>`)은 서버의 홈과 **같은 폴더**라서(마운트), 등록한 키는 서버의 `~/.ssh/authorized_keys`(권한 600)에 그대로 들어가고 바로 로그인에 쓰입니다. 관리자가 해 줄 일은 없습니다.
  - 키로 접속해도 위와 같이 개발환경 안으로 들어갑니다(포트 전달 차단 동일).

## 3. 파일 올리기·내려받기

`https://files.<도메인>/` (SFTPGo, 파일 서비스를 설치한 경우) 에 내 ID 와 **현재 비밀번호**로 로그인합니다. SFTP 클라이언트는 `<서버 주소>` 포트 `2022` 입니다. 개발환경 안의 작업 폴더는 `/workspace` 이고 내 workspace 는 설정에 따라 다른 회원이 읽을 수 있습니다(관리자에게 확인).

## 4. 웹 공개와 내 DB

직접 외우지 마세요. 개발환경의 AI 에이전트에게 «이 프로젝트를 웹에 공개해 줘» / «DB 가 필요해» 라고 하면 스킬 `<접두어>-publish` 가 절차를 안내합니다.

- 정적 페이지는 `/workspace/<프로젝트>/publish/` 폴더의 파일이 `https://<ID>.<도메인>/<프로젝트>/` 로 공개됩니다.
- **폴더에 둔 파일은 곧 공개됩니다.** 비밀번호·키·`.env`·개인정보는 넣지 마세요.
- DB 는 회원 등록 때 자동으로 만들어집니다(ID 에 하이픈이 있으면 건너뜀). 비밀번호는 `~/.pgpass` 에서만 읽고 출력·공유하지 마세요.
