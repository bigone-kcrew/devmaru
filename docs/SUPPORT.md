# 도움 요청과 진단 묶음

설치·운영 중 문제가 생기면 **진단 묶음**을 만들어 이슈(또는 담당자)에게 전달하세요. 상태를 읽기만 하고 서버를 바꾸지 않습니다.

```bash
sudo <접두어>-support-bundle                # /root/<접두어>-support-<호스트>-<날짜>.tar.gz (권한 600)
sudo <접두어>-support-bundle --out /tmp --lines 500   # 폴더·로그 줄 수 지정
sudo <접두어>-support-bundle --selftest     # 마스킹 자체 시험만(가짜 토큰이 지워지는지)
```

## 들어 있는 것 / 없는 것

| 포함 | 제외 |
|---|---|
| `doctor --json` 결과 · `site.env`(비밀 없음) · 모듈 목록 | `*.env` · `secrets/` · 토큰 · 페어링 링크 |
| 설치 로그·Golden 빌드 로그의 마지막 N줄 · `state.json` | 회원 대화 · workspace · 회원 홈 · DB 내용 |
| `docker ps`·이미지 태그·컨테이너 상태(재시작 수·OOM) | 회원 개발환경(`dev-*`) 컨테이너 로그 |
| 디스크·메모리 · OS·커널 · 킷 버전 | |
| 서비스 컨테이너(postgres·caddy·n8n 등) 로그 꼬리 · caddy 로그 | |

## 마스킹과 자체 검사

- 모든 텍스트에서 토큰(GitHub·OpenAI 형식·Slack·AWS·Google 키·JWT), 개인키, `PASSWORD`/`SECRET`/`TOKEN`/`KEY` 가 들어간 이름의 값, `Bearer`, URL 속의 `사용자:비밀번호@`, 페어링 링크(`offer=`), 40자 이상 16진수, 이메일 앞부분을 `[MASKED…]` 로 바꿉니다.
- 실행할 때마다 먼저 가짜 토큰으로 **마스킹 자체 시험**을 하고, 묶기 직전에 결과물에 토큰 패턴이 0건인지 다시 검사합니다. 남아 있으면 묶지 않고 중단합니다.
- 알려진 패턴만 지웁니다. **도메인 · 회원 ID(컨테이너 이름) · 서버 IP** 는 그대로 들어 있습니다.

> **이슈에 첨부하기 전에 직접 열어 확인하세요.**
> `tar -tzf <파일>` 로 목록을, `tar -xzOf <파일> <접두어>-support/30-site.env | less` 로 내용을 봅니다. 공개 이슈라면 민감해 보이는 줄은 지우고 올리세요.

## 에이전트(AI) 계정에 허용할지 — 제안(문서 제안일 뿐 현재 허용 목록에는 없음)

`support-bundle` 은 읽기 전용이고 비밀을 마스킹하지만 root 로 `docker logs` 등을 읽습니다. `agent` 모듈의 sudo 허용 목록에 넣을지는 **관리자가 판단**하세요. 넣는다면 인자 없는 형태와 `--out` 고정 폴더만 허용하는 것을 권합니다(와일드카드 인자 금지). 허용하지 않으면 관리자가 `! sudo <접두어>-support-bundle` 을 직접 실행하게 합니다.
