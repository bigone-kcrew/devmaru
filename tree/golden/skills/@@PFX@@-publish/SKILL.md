# 웹 공개와 내 DB

@@BRAND@@ 멤버는 관리자 승인 없이 프로젝트를 웹으로 공개하고, 멤버당 PostgreSQL DB 하나를 쓴다.
**주소는 허용 IP 에서만 열린다.** 이 Skill 은 절차와 규칙을 담는다. 먼저 아래 세 가지는 어떤 경우에도 지킨다
(전역 지침에도 같은 내용이 있다).

1. **공개하기 전에 사용자에게 무엇이 공개되는지 보여 주고 확인을 받는다.** 로그인이 없으면 «누구나 볼 수 있다» 고 말한다.
2. **비밀·키·토큰·`.env`·개인정보는 공개 폴더, 코드, compose, 로그에 넣지 않는다.**
3. **DB 비밀번호는 `~/.pgpass` 에서만 읽게 한다.** 출력하거나 파일·대화에 옮기지 않는다.

## 파일은 어디에 두나

| 무엇 | 어디 | 비고 |
|---|---|---|
| 프로젝트 문서·자료 | `/workspace/<프로젝트>/` | 내 workspace 는 나와 관리자만 열 수 있다. |
| 서버 앱 소스·가상환경 | `/workspace/<프로젝트>/app/` | 앱이 여럿이면 `app/<앱이름>/`, 가상환경은 `app/.venv`. `app/`·`publish/` 는 필요할 때 만든다(미리 만들어 두지 않는다). |
| 정적 페이지(공개 파일) | `/workspace/<프로젝트>/publish/` | 이 폴더 안의 파일만 공개된다. |
| 비밀·개인정보(`.env`·키·서명·DB 덤프) | `/workspace/<프로젝트>/.private/` | 폴더 700, 파일 600, git 제외. 홈에 두지 않는다. **공유 폴더(`/shared`)에는 두지 않는다** — 멤버 전원이 읽을 수 있다. |
| 멤버끼리 함께 쓰는 프로젝트 | `/shared/workspaces/<프로젝트>/` | `@@PFX@@-shared-workspace-create`. `/shared` 바로 아래에는 쓰지 않는다. |
| 홈(`~`) | 도구·인증 파일 전용 | `.codex` `.claude` `.ssh` `.pgpass` 등. 프로젝트 파일을 두지 않는다. |

## 어느 쪽인가

| 상황 | 방법 |
|---|---|
| HTML·CSS·JS·이미지처럼 파일만 있다 | **정적 페이지** — `publish/` 폴더 (`@@PFX@@-site`) |
| 멤버 여럿이 함께 만든 정적 페이지 | **공용 정적 페이지** — `/shared/workspaces/<프로젝트>/publish/` |
| Django·FastAPI·Flask·Node 처럼 프로세스가 돌아야 한다 | **서버 앱** — `@@PFX@@-app publish` (공용 앱도 같은 방식) |
| 데이터를 저장해야 한다 | 서버 앱 + **내 DB** (`@@PFX@@-app db`) |

정적 파일로 충분하면 서버 앱을 만들지 않는다. **`publish/` 는 정적 페이지 전용이다.** 서버 앱은 `publish/` 를 쓰지 않는다.
한 프로젝트가 둘 다 가질 수 있다(`publish/` 정적 페이지 + 별도 서버 앱).

## 정적 페이지

- `/workspace/<프로젝트>/publish/` 폴더를 만들고 파일을 두면 `https://<멤버ID>.@@DOMAIN@@/<프로젝트>/` 로 열린다.
  **내용 수정은 바로 반영된다.** 새 프로젝트 폴더를 만들거나 `publish/` 폴더를 지웠다 다시 만들면 **최대 1분** 뒤에 열린다.
  `@@PFX@@-site init <프로젝트>` 는 폴더 만들기와 확인을 한 번에 한다.
- **폴더를 만들거나 안에 쓰기 전에 사용자 확인을 받는다.** 폴더가 곧 공개다.
- 공개 전에 `@@PFX@@-site check <프로젝트>` 를 돌리고 나온 문제를 전부 사용자에게 알린다.
- 넣지 않는 것: 바로가기(심볼릭 링크), `.env`, 키·토큰·비밀번호·인증서, DB 파일, 개인정보, 남의 자료. 필요한 파일은 링크하지 말고 복사한다.
  `publish/` 폴더 자체를 링크로 만들면 공개되지 않는다. 점(.)으로 시작하는 파일과 비밀처럼 보이는 이름(`.env`, `*.key`, `*secret*`, `*token*`, `*.sqlite`, `*.sql` 등)은 서버가 열어 주지 않는다. 그래도 이것에 기대지 않는다.
- HTML 의 경로는 상대경로(`css/a.css`)로 쓴다. `/css/a.css` 처럼 /로 시작하면 `/<프로젝트>/` 아래에서 열리지 않는다.
- `@@PFX@@-site list` 로 목록, `@@PFX@@-site off <프로젝트>` 로 공개를 멈춘다(파일은 그대로 남는다).

### 공용 정적 페이지

- `/shared/workspaces/<프로젝트>/publish/` 에 파일을 두면 `https://@@PORTAL_HOST@@/<프로젝트>/` 로 열린다(허용 IP 전용). 같은 규칙이 자동으로 적용된다.
  - 프로젝트 이름은 소문자로 시작하는 영문 소문자·숫자·하이픈 2~31자, `ops`·`skills`·`tools` 같은 예약어와 포털 파일 이름은 쓸 수 없다.
  - `publish/` 는 실제 폴더여야 하고(링크 불가), 프로젝트 폴더 소유자가 현재 멤버여야 한다. 공유 프로젝트는 최대 10개.
- 공유 폴더는 멤버 모두가 쓸 수 있으니 **공개 전에 모든 참여자가 알고 있는지 사용자에게 확인한다.** 공개는 OPS 에 표시된다.
- 소유자 계정이 삭제되면 자동으로 공개가 중지된다. 끄려면 `@@PFX@@-site off <프로젝트 또는 폴더 경로>`(공용인지는 폴더 위치로 자동 판별).
- 규칙에 맞지 않으면 공개되지 않고 `@@PFX@@-site list` 에 사유가 나온다 — 우회하지 말고 사용자에게 전한다.

## 서버 앱

앱은 **내 개발 컨테이너 안에서** 돌고, 서버가 `https://<앱이름>.@@DOMAIN@@` 를 앱 포트로 이어 준다.
소스는 `/workspace/<프로젝트>/app/`(앱이 여럿이면 `app/<앱이름>/`)에 두고, 비밀은 `/workspace/<프로젝트>/.private/` 에서 읽게 한다.
**공용 앱도 같은 방식이다.** 소스를 `/shared/workspaces/<프로젝트>/` 에 두고 한 멤버가 자기 컨테이너에서 `@@PFX@@-app publish` 를 낸다.
그 앱은 낸 멤버의 앱 개수·만료·컨테이너에 묶이고, 주소는 `<앱이름>.@@DOMAIN@@` 하나뿐이다.
**공용 앱의 비밀은 `/shared` 에 두지 않는다.** 앱을 낸 멤버의 `/workspace/<자기 프로젝트>/.private/` 에 두고 앱이 그 경로에서 읽게 한다.

1. **앱을 점검한다.** 개발 서버·디버그 모드로 공개하지 않는다(gunicorn·uvicorn·`node server.js` 같은 운영용 서버, debug 끔).
   허용 호스트와 신뢰 출처를 앱 주소(`<앱이름>.@@DOMAIN@@`)로 맞춘다(Django 는 `ALLOWED_HOSTS`·`CSRF_TRUSTED_ORIGINS`).
   앱은 `0.0.0.0:<포트>` 로 들어야 한다(localhost 만 들으면 열리지 않는다).
2. **포트를 고른다.** `@@PFX@@-app ports` 가 내 포트 범위(멤버마다 10개)와 지금 적용되는 규칙(개수·기간 한도)을 보여 준다.
   안내가 «아직 안내 파일이 없습니다» 로 나오면 포트를 짐작하지 말고 관리자에게 범위를 묻는다.
3. **사용자 확인을 받는다.** 어떤 앱이 공개되는지, 로그인이 없는지, 앱에 개인정보를 받는 화면·열람 화면이 있는지를 말한다.
   **로그인 없이 개인정보를 «열람»하는 화면은 공개하지 않는다.** 신청서처럼 «수집»만 하는 공개 화면은 입력·저장을 최소로 하고, 열람·관리자 화면은 앱 자체 인증(OTP 등)을 건다.
4. **공개 요청을 낸다.**

   ```text
   @@PFX@@-app publish <앱이름> <포트> [--dir <앱 폴더>] [--basic] [--days N] [--start "<시작 명령>"]
   ```

   * `--dir <앱 폴더>`: 앱 소스 폴더(예: `/workspace/<프로젝트>/app`). 서버가 앱과 프로젝트의 연결을 기록하고 `--start` 의 기본 작업 폴더로 쓴다. 생략하면 현재 폴더가 `/workspace/<프로젝트>/app/` 아래일 때 그 폴더를 쓴다.
   * `--basic`: 서버가 앱 전체에 비밀번호 창을 붙인다(정보는 `@@PFX@@-app password <앱이름>`). 공개 신청서처럼 **누구나 들어와야 하는 화면에는 쓰지 못한다**
     — 그런 앱은 앱 자체 로그인으로 관리자 화면을 막는다.
   * `--days N`: 공개 기간. 생략하면 기본값.
   * `--start`: 컨테이너가 다시 만들어진 뒤 앱이 꺼져 있으면 서버가 이 명령으로 다시 켠다. **상시 공개하는 앱에는 등록한다.**
     시작 명령은 **홈에서 시작한다.** `--dir` 을 쓰지 않았다면 `"cd /workspace/<프로젝트>/app && ./run.sh"` 처럼 앱 폴더로 이동하는 부분을 꼭 넣는다.
     명령에 비밀을 넣지 않는다(환경 파일에서 읽게 한다). 로그는 `@@PFX@@-app log <앱이름>`.
5. **결과를 확인한다.** `@@PFX@@-app status <앱이름>` 이 «공개됨» 이면 된다. 거부되면 사유가 그대로 나온다
   (예약된 이름, 이미 쓰이는 이름, 포트 범위 밖, 앱 수 초과 등) — 우회하지 말고 사유를 사용자에게 전한다.
6. 새 앱의 시작 틀은 `@@PFX@@-app template django|fastapi|node [폴더]` 로 만든다(폴더를 생략하면 현재 프로젝트의 `app/`. 운영용 설정이 들어 있고, 비밀 파일 경로는 프로젝트의 `.private/` 를 쓴다.
   Flask 같은 다른 프레임워크는 포트와 시작 명령만 맞으면 된다).

관리: `@@PFX@@-app list` · `@@PFX@@-app status [앱]` · `@@PFX@@-app renew <앱> [--days N]`(연장) · `@@PFX@@-app off <앱>`(공개 중지 — 앱 프로세스는 직접 끈다) · `@@PFX@@-app log <앱>`.

## 한도와 만료

정확한 값은 `@@PFX@@-app ports` 가 보여 주는 규칙이 정본이다. 2026-10-23 기준:

* 멤버당 앱 **5개**, 요청 본문 **10MB**.
* 기본 **30일** 뒤 자동으로 닫힌다. `--days` 나 `@@PFX@@-app renew` 로 한 번에 최대 **365일**. 닫혀도 데이터와 DB 는 남는다.
* 만료 14일 전에 **관리자에게** 알림이 가고, `@@PFX@@-app status` 에 남은 일수가 보인다. 멤버에게 직접 가는 알림은 없으니 사용자에게 가끔 알려 준다.
* **운영 앱**: 오래 운영할 서비스는 관리자에게 «운영 앱 지정»을 요청한다(만료 없음). **직접 지정하거나 만료를 우회하지 않는다.**
* 한도를 넘겨야 하면 관리자에게 알린다.

## 내 PostgreSQL

* DB 는 멤버당 하나(`<멤버ID>_db`)다. 연결은 20개까지이고 다른 사람 DB·중앙 DB 에는 접속할 수 없다.
* 먼저 `@@PFX@@-app db status`. 준비되지 않았다고 나오면 사용자에게 알리고 관리자에게 요청하게 한다(스스로 만들 수 없다).
  `postgres` 이름을 찾지 못한다는 오류가 나면 앱 문제가 아닐 수 있다(서버 쪽 연결 문제) — 관리자에게 알린다.
* **앱마다 스키마를 따로 쓴다.** `@@PFX@@-app db schema <앱이름>` 으로 만들고, 앱에는 `DB_SCHEMA=<앱이름>`(Django 시작 틀이 이미 적용) 또는 `search_path` 로 알린다.
  `public` 에 앱 테이블을 만들지 않고 다른 앱의 스키마를 건드리지 않는다.
* `@@PFX@@-app db dsn` 은 호스트·DB·사용자만 알려 준다. 비밀번호는 `~/.pgpass` 에서 읽게 한다(Django 시작 틀은 이미 그렇게 되어 있다).
  `@@PFX@@-app db psql` 로 직접 SQL 을 실행한다.
* **멤버 DB 는 서버 백업에 포함되지 않는다.** `@@PFX@@-app db backup` 은 DB 전체를 `/workspace/.db-backups`(나와 관리자만 열 수 있다)에 최근 7개 남길 뿐이다.
  중요한 데이터면 사용자에게 따로 보관하라고 알린다. 덤프에는 모든 앱의 데이터가 들어 있으니 `publish/` 나 공유 폴더로 옮기지 않는다.
* 멤버 계정이 삭제되면 DB 는 90일 보관 뒤 정리된다(그 안에 같은 ID 로 다시 만들면 되살아난다).

## 개인정보·요청 폭주

* 로그인이 없는 공개 서비스는 국내 누구나 접속할 수 있다. 개인정보를 받는 서비스는 입력·저장·열람을 최소로 하고, 열람 화면은 앱 자체 인증을 건다.
* 개인정보·비밀 파일은 `/workspace/<프로젝트>/.private/`(700·600)에 두고 `publish/`·공유 폴더·git 에 넣지 않는다.
* 서버에는 요청 횟수 제한이 없다. 인증번호 발송처럼 비용이 드는 요청의 제한(전화번호별·IP별)은 **앱 안에서** 구현한다.
* **접속자 IP 와 http/https 는 서버 프록시가 보낸 값만 믿는다.** `@@PFX@@-app ports` 끝에 «서버 프록시 주소»가 나온다.
  앱은 접속 상대 주소(peer)가 그 주소일 때만 `X-Forwarded-For`(가장 오른쪽 값)·`X-Forwarded-Proto` 를 믿고, 그 외 접속에서는 peer 주소를 접속자 IP 로, 스킴은 http 로 본다.
  `X-Real-IP`·`Forwarded`·`True-Client-IP` 는 읽지 않는다. 같은 서버의 다른 컨테이너는 프록시를 거치지 않고 앱 포트에 직접 접속해 헤더를 위조할 수 있기 때문이다.
  이 때문에 허용 IP 제한이나 `--basic` 은 같은 서버 안 접속을 막아 주지 않는다 — 관리자 화면은 앱 자체 인증에 기댄다.
* 외부 API 키는 환경 파일에서 읽고 코드·로그·화면에 남기지 않는다.

## 서버 안에서 내 앱 확인하기

1. **공개 URL 로 바로 연다.** 서버 안(내 컨테이너)에서도 `https://<앱>.@@DOMAIN@@` 이 열린다. 허용 IP 제한은 서버 밖 해외 IP 에만 걸린다.
2. **막히면 호스트를 로컬로 돌려 연다.** URL 에 **포트를 반드시 적는다**(생략하면 크롬이 https 로 올려 차단한다).
   `agent-browser --session <내이름> --args "--host-resolver-rules=MAP <호스트> localhost" open http://<호스트>:<포트>/`
3. **대안.** `http://localhost:<포트>` 로 열고, 앱이 호스트를 검사하면 `ALLOWED_HOSTS`(또는 같은 설정)에 `localhost` 를 넣는다.
4. **세션 이름은 자기 것을 쓴다.** `agent-browser close --all` 은 다른 세션까지 닫으니 쓰지 않는다.

## 안 열릴 때

| 증상 | 확인 |
|---|---|
| 컨테이너 안에서 공개 주소를 열면 403 | 서버 안 접속은 허용된다. 계속 403 이면 위 «서버 안에서 내 앱 확인하기» 의 2번(호스트 로컬 매핑)으로 확인하고, 그래도 안 되면 국내 PC·휴대폰 브라우저로 확인하라고 한다. |
| 해외·VPN 에서 403 | 허용 IP 전용이다. |
| 정적 페이지가 안 열린다(새 폴더) | 만든 뒤 최대 1분 기다린다. `@@PFX@@-site check`·`@@PFX@@-site list` 로 사유를 본다. `publish/` 가 링크이거나 이름·위치 규칙에 안 맞으면 열리지 않는다. |
| 폴더를 지우고 다시 만든 뒤 정적 페이지가 비었다 | 최대 1분 기다린다. 계속 비면 `@@PFX@@-site list` 를 확인한다. |
| 특정 파일만 404 | 점 파일이거나 비밀처럼 보이는 이름이다. 이름을 바꾸거나 공개할 파일이 맞는지 사용자에게 확인한다. |
| `@@PFX@@-app status` 가 거부 사유를 보여 준다 | 사유대로 고친다(이름·포트·개수). |
| «서버 설정 검증이 실패해 아직 공개되지 않았습니다» | 서버가 자동으로 다시 시도한다. 계속되면 관리자에게 알린다. |
| 공개됨인데 502·빈 화면 | 앱이 `0.0.0.0:<포트>` 로 떠 있는지, 요청한 포트와 같은지 본다(`@@PFX@@-app log`). |
| 컨테이너를 다시 만든 뒤 앱이 꺼졌다 | `--start` 가 없었다. 앱을 다시 켜고 `@@PFX@@-app publish` 를 `--start` 와 함께 다시 낸다. `--start`(또는 `--dir`)가 앱 폴더 `/workspace/<프로젝트>/app` 을 가리키는지도 본다. |
| 만료됨 | `@@PFX@@-app renew <앱이름>`. 상시 서비스면 운영 앱 지정을 요청한다. |

## 하지 않는 것

* 관리자 승인 절차, Caddy·서버 설정을 우회하거나 직접 바꾸려 하지 않는다.
* 다른 멤버의 포트·이름·DB·workspace 를 쓰지 않는다.
* 사용자 확인 없이 공개하거나, 로그인 없이 개인정보를 «열람»하게 공개하지 않는다.
* 비밀·개인정보를 홈이나 `publish/`·공유 폴더에 옮기지 않는다.
